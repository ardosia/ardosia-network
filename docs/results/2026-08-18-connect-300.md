# connect-300 baseline — 2026-08-18

> **Historical evidence:** this report records the repository, toolchain, vendoring model, workflow, and benchmark harness as they existed at measurement time. Those details are intentionally preserved as provenance and are **not current setup instructions**. The active repository now uses Rust `1.98.0`, depends on the public `ardosia-raknet` hardfork by exact Git revision, and no longer contains the old load generator/benchmark workflow. See the repository README for current development instructions.

## Purpose

Establish the first correctness baseline for the Ardosia RakNet transport before adding realistic traffic and higher concurrency.

This result measures connection establishment and session survival only. It is intentionally not a throughput or production-capacity claim.

## Configuration at measurement time

- Scenario: `scenarios/connect-300.toml`
- Clients: 300
- RakNet protocol: 8
- Ramp-up: 10 seconds
- Hold: 60 seconds
- Per-client connect timeout: 5 seconds
- Transport: `ardosia-network` backed by the then-vendored `mcbe-rs/raknet-rust`
- Vendor revision: `3edfb4170e6cb5aeed992b09b50176fb7e5b6079`
- Rust: 1.88.0
- Runner: GitHub-hosted Ubuntu 24.04

The vendored layout above is historical. The current repository instead pins the public Ardosia RakNet hardfork by Git revision.

## Scope limitations

This baseline did not exercise:

- sustained unreliable movement-like traffic;
- reliable ordered application traffic under load;
- server broadcast/fanout;
- fragmentation frequency beyond regression tests;
- packet loss or jitter;
- connection churn;
- RTT p50/p95/p99;
- CPU or RSS;
- ACK/NACK and retransmission rates;
- queue/window pressure;
- 500- or 1000-session characterization.

Later historical experiments covered churn and 1000-session profiling and are preserved in the neighboring dated reports. The old benchmark phase is complete and the harness is no longer current development infrastructure.

The conclusion from this run remains intentionally narrow: this exact historical protocol-8 transport configuration established and held 300 localhost sessions cleanly under this scenario. It is not a universal production-capacity claim.
